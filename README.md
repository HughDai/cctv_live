# cctv_live · 小米电视央视直播

原生 Android TV 应用，包名 `com.hughdai.cctvlive`，版本 1.0.9。支持 Android 5.0 及以上；实机目标为小米 L55MA-SPL、HyperOS Android 14。

## 操作

| 按键 | 功能 |
|---|---|
| 上 / 下 | 切换频道，首尾循环；连续按键合并切换 |
| 左 / 右 | 切换线路；全部失败后可重新尝试 |
| 确定 | 打开频道列表；列表内确定播放 |
| 返回 | 关闭列表或设置；观看时确认退出 |
| 菜单 | 更新源、检查 App 更新、支持一下开发、修改订阅、画质偏好、诊断、恢复内置源 |

每台内置至少一条线路，健康播放20秒后记住频道和成功线路。持续或累计频繁缓冲/连接失败会有限重试并自动尝试其他线路，全部失败后停止，避免无限闪屏。返回前台重新连接当前频道。

设置中的“自动”由 Media3 对源提供的多码率轨道自适应选择。固定720p/1080p地址无法由客户端转码，卡顿时尝试其他源，不能保证一定存在更低画质。流畅偏好针对多码率源优先720p；固定画质源仍可能超过这一分辨率。

## 播放源

内置地址与出处记录在 `app/src/main/assets/channels.json`。公开源会改变或失效，电视上的实际画质和节目台标才是判断依据。源探测成功不代表长期稳定。

CCTV-1、2、4、7、9、10、12、13、17 使用央视新闻官方动态入口，播放时自动取得当次签名；无需手动更新临时地址。官方各低画质档位作为显式备用线路，卡顿时按失败策略降档。导出的M3U包含官方短效地址快照，到期后外部播放器需重新取得；App自动刷新。

默认订阅：`https://raw.githubusercontent.com/best-fan/iptv-sources/main/cn_cctv_status.m3u8`。启动先使用本地配置，距上次成功更新超过一天时在后台尝试更新，也可手动更新或改为自己的 HTTPS 订阅。GitHub 在大陆可能访问失败，失败会保留旧列表。

支持 UTF-8 M3U 与本项目频道 JSON 格式。接收 CCTV-1～17 和 CCTV-5+，排除4K和CCTV-4欧美版；CCTV-5+ 在 JSON 中使用稳定编号105，排列在5与6之间。保留已验证内置源，优先接收本次新订阅地址，再补历史地址；每台最多8条，去除重复及本次已确认的误标/异常线路。新订阅源不会中断正在播放的视频，下次换台或重启生效。恢复内置源不会清除频道记忆。

## 构建

需要 JDK17～21、Android SDK34 / Build Tools34 和互联网连接（首次下载依赖）。

1. Android Studio 打开此目录，配置 SDK；或在 `local.properties` 设置 `sdk.dir`。
2. `sh test-core.sh` 运行纯Java行为测试。
3. `./gradlew assembleRelease lintRelease` 构建与检查。
4. APK 在 `app/build/outputs/apk/release/app-release.apk`。

本次交付 release APK 关闭调试，沿用本机原型的开发签名便于覆盖安装。源码默认沿用构建电脑的 Android 开发签名；换电脑后签名可能不同，不能直接更新现有安装。发布到其他设备前应配置并妥善保管独立签名，不将私钥放进源码包。

Debug 构建才允许 `probe_channel`、`probe_source`、`probe_bad_first` 的 ADB 验收参数；release 忽略这些参数。

## 安装到已授权的电视

```sh
adb connect 192.168.0.105:5555
adb -s 192.168.0.105:5555 install -r cctv_live-1.0.9.apk
```

## GitHub 更新

App 会在设置中通过 `HughDai/cctv_live` 的 GitHub Releases 检查更新。新版本使用 `cctv_live-版本号.apk` 命名；大陆网络无法访问 GitHub 时，检查失败不会影响当前版本播放。

## 支持开发

设置中有“支持一下开发”入口，支付宝和微信收款码已内置在 APK 中。觉得小电视还算顺手，可以给它补一点“电量”；不支持也完全没关系，能正常看节目就是最好的反馈。

不需要账号。没有EPG、收藏、开机自启。仅访问直播与配置地址，缓存保存在应用私有目录，未加入统计服务。

设备配置测试（使用独立缓存目录和偏好文件，不影响观看记忆）：

```sh
./gradlew assembleDebug assembleDebugAndroidTest
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb shell am instrument -w com.hughdai.cctvlive.test/com.hughdai.cctvlive.CatalogInstrumentation
```

测试完请覆盖安装 release APK，并卸载测试包 `com.hughdai.cctvlive.test`。

默认订阅按频道仅导入本次已验证的源站入口，避免自动加入未核对地址。要使用其他源站，可修改为自己的 HTTPS 订阅；新地址仍需核对频道内容。

## 2026-10-26 广告源处理

直接抓取 CCTV-1 的视频流，确认 `74.91.26.218` 入口出现血糖及药品销售广告。移除该服务器入口并按主机过滤，旧缓存、订阅和恢复内置源均应用此过滤。并未据此断言同服务器每个频道都已观察到广告。替代源以本次电视实测分辨率记录；一分钟通过不代表长期稳定或永远无广告。

验收边界：用户接受央视原播广告，只排除转播额外插播。原流含卖药画面并不能单独证明具体插入方，也不能推断同IP所有频道都额外插播。对其整体隔离按用户指定范围处理。

## 1.0.3 主线路画质

18个频道的内置主线路均配置为经过电视验证的1080P入口。CCTV-5、11、15补入本轮1080P来源，旧低画质线路移为备用。实际播放仍可能因源站或网络异常自动切到备用线路，界面显示的是实际解码尺寸。最终逐台结果见本次1.0.3验收记录。

## 1.0.4 备用线路完整性

18个频道均至少包含两条线路。CCTV-3、CCTV-5+、CCTV-6、CCTV-8、CCTV-14、CCTV-16 新增的线路均在目标电视连续播放一分钟，并核对频道台标和节目；主线路顺序保持不变。

## 1.0.5 应用图标

应用图标更换为用户提供的透明 CCTV Logo。原始宽高比保持不变，图像等比例缩放并居中放入透明正方形画布；电视桌面横幅保持原样。

## 1.0.6 白色图标背景

应用图标画布改为纯白色 `#FFFFFF`，CCTV Logo 的尺寸、宽高比和居中位置保持不变；电视桌面横幅保持原样。

## 1.0.7 线路耗尽自动恢复

所有线路在一轮内均失败后不再永久停留在错误提示。App 会在 30 秒后从主线路重新开始，并在连续失败时依次退避到 60、120、240、300 秒；任一线路连续稳定播放 20 秒后，恢复为 30 秒起步。播放器错误、流结束和有效播放状态下连续缓冲 15 秒仍会触发原有切源逻辑。

## 1.0.8 CCTV-3 主线路调整

将本次现场正常播放的 1080P 备用线路提升为 CCTV-3 主线路；发生过短时连接中断、随后复测近两分钟正常的原主线路降为备用，不删除该线路。
